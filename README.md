# Machine Learning-Based Network Intrusion Detection System

A reproducible research project evaluating classical machine learning methods for network intrusion detection using the CIC-IDS2017 benchmark dataset.

---

## Overview

This project trains and compares four CPU-friendly ML classifiers — Logistic Regression, Random Forest, HistGradientBoosting, and XGBoost — on labeled network flow records from the CIC-IDS2017 dataset. The goal is not to claim state-of-the-art performance, but to conduct a rigorous, honest experiment that demonstrates end-to-end ML research competence: data inspection, leakage-free preprocessing, model comparison, error analysis, feature importance, and critical discussion of limitations.

All results are generated by actually running the code. No metrics are fabricated or manually adjusted.

---

## Research Motivation

Network intrusion detection systems (IDS) are a critical component of cybersecurity infrastructure. Traditional signature-based IDS cannot detect novel attacks. Machine learning approaches can potentially learn attack patterns from labeled data, but face challenges including class imbalance, concept drift, false alarm rates, and computational constraints. This project investigates whether classical ML methods can achieve reliable detection on a benchmark dataset, and what limitations emerge that motivate further research.

---

## Research Questions

1. Can classical ML classifiers reliably distinguish malicious from benign network traffic on CIC-IDS2017?
2. Do class imbalance handling strategies substantially improve detection performance?
3. Which network flow features are most discriminative, and do they have a plausible security interpretation?
4. What are the false positive and false negative characteristics of each model?
5. What limitations of the dataset and experimental setup constrain the conclusions?

## Methodology

### Data Preprocessing
- Replaced ±∞ values with NaN (4,376 values in rate features)
- Dropped 256,684 duplicate rows (9.07%)
- Dropped `Destination Port` and duplicate `Fwd Header Length.1`
- Stratified 80/20 train/test split (random_state=42)
- StandardScaler + median imputation fitted **on training data only** (no leakage)
- 200,000-row stratified subset used due to ~8 GB RAM constraint

### Models

| Model | Key Parameters |
|-------|---------------|
| Logistic Regression | max_iter=1000 |
| Random Forest | 100 trees |
| HistGradientBoosting | max_iter=100 |
| XGBoost | tree_method="hist" (CPU), 100 trees |

### Imbalance Strategies
- None (baseline)
- Class weights (balanced)
- RandomUnderSampler
- SMOTE (applied after split and after scaling)

## Evaluation Metrics

Primary: **Macro F1** (appropriate for imbalanced classes)  
Secondary: Accuracy, Precision, Recall, F1, ROC-AUC, PR-AUC  
Error analysis: False Positive rate, False Negative rate

For cybersecurity, accuracy alone is insufficient. A classifier predicting all flows as BENIGN would achieve 83.5% accuracy on this dataset while missing every attack.

## Feature Analysis

Feature importances from XGBoost (top features by Gini gain):
- Flow-rate features (Flow Bytes/s, Flow Packets/s) — discriminate DoS/DDoS
- Packet length statistics (Mean, Variance) — attack payload size differences
- Inter-arrival time (IAT) features — timing patterns characteristic of attacks
- TCP flag counts (SYN, FIN, RST) — protocol-level attack signatures

Feature importance plots saved to `results/figures/feature_importance_*.png`.

## Error Analysis

| Model | False Positives | False Negatives | Notes |
|-------|----------------|-----------------|-------|
| XGBoost | 29 | 25 | Lowest FN rate (0.38%) |
| HistGradientBoosting | 28 | 32 | Similar to XGBoost |
| Random Forest | 26 | 53 | Lowest FP count |
| Logistic Regression | 867 | 965 | FN rate 14.58% — operationally problematic |

False negatives (missed attacks) are the more critical error type in security applications. XGBoost's 0.38% FN rate is substantially better than Logistic Regression's 14.58%.

---

## Limitations

1. **Single dataset** — no cross-dataset validation
2. **200K-row subset** — 7.8% of available data due to RAM constraint
3. **2017 vintage** — modern attacks not represented
4. **Lab environment** — traffic synthetically generated, not real enterprise traffic
5. **Rare classes unlearnable** — Heartbleed (11 samples), Infiltration (36 samples)
6. **No hyperparameter tuning** — default parameters used
7. **No deployment testing** — no evaluation on live traffic

---

## Future Research

Motivated by specific experimental findings:

1. **Anomaly detection for rare classes** — Heartbleed/Infiltration unlearnable by supervised methods
2. **Concept-drift-aware IDS** — 2017 models would degrade on modern traffic
3. **Explainable IDS** — SHAP-based alert explanations for analyst trust
4. **Cross-dataset generalization** — quantify performance gap on NSL-KDD, UNSW-NB15
5. **Federated IDS** — privacy-preserving collaborative training across organizations

## Usage

### Step 1: Download Dataset
See `data/README.md` for instructions. Place CSV files in `data/raw/`.

### Step 2: Run Preprocessing
```bash
python run_preprocessing.py
```
Outputs: `data/processed/X_train.npy`, `data/processed/X_test.npy`, etc.

### Step 3: Run EDA
```bash
python run_eda.py
```
Outputs: figures in `results/figures/`

### Step 4: Run Experiment
```bash
python run_experiment.py --task binary
```
Outputs: metrics in `results/metrics/`, comparison in `results/tables/`

### Step 5: Run Multiclass Experiment
```bash
python run_multiclass.py
```

## Reproducibility

All experiments are reproducible with:
- `random_state=42` passed to all stochastic operations
- Pinned dependency versions in `requirements.txt`
- Fixed train/test split (80/20 stratified)
- Preprocessing pipeline fitted on training data only
- Subset sampling with fixed seed

To reproduce from scratch on the same hardware:
1. Download dataset per `data/README.md`
2. Run `python run_preprocessing.py`
3. Run `python run_experiment.py --task binary`

Results will match those in `results/metrics/` and `results/tables/model_comparison.csv`.
